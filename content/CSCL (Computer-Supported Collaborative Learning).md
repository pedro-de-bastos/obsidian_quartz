The field of learning that describes the use of computers to regulate and structure collaborative learning processes (Dillenbourg, 2002).

Dillenbourg (2002) discusses the use of 'scripts', i.e. established learning plans, that students follow in groups in order to learn collaboratively. These 'scripts' often include the use of computer tools for interactive activities, like building a 'grid' of concepts in a table, where each student contributes with a set number of concepts.

Dillenbourg shares a few insights about building these scripts:

**For Designing Effective Scripts:**

- **Balance Coercion:** While some coercion is needed for efficiency, too much can destroy student motivation and the "natural" benefits of collaboration .
    
- **Distribute Constraints:** Instead of concentrating constraints heavily on one aspect (like a rigid dialogue interface), distribute smaller constraints across the task, division of labor, timing, and tutoring.
    
- **Prioritize Simplicity:** Scripts must be simple enough for students and tutors to "appropriate" (adopt) without high cognitive load. Complex scripts (like the initial UniverSanté) often fail.
    
- **Integrate Face-to-Face:** Do not exclude face-to-face activities if possible; use synchronous activities for key phases and asynchronous ones for others to manage organizational constraints.
    
- **Design for Internalization:** Aim for scripts that students can eventually "internalize," allowing them to individually perform the cognitive processes that were previously distributed among the group (a Vygotskian approach).
    

**For Managing the Learning Environment:**

- **Use Scripts as Time Management:** In distance education, use the script to set a clear time frame and routine, as students often lack these landmarks.
    
- **Allow Flexibility:** Scripts should be malleable enough to allow students to adapt them to their own preferred mode of collaboration to avoid interaction breakdowns.
    
- **Make Design Choices Explicit:** If a designer builds a script that is not strictly collaborative (e.g., for efficiency), this should be an explicit design choice rather than an accidental drift.

Dillenbourg, P. (2002). Over-scripting CSCL: The risks of blending collaborative learning with instructional design. _Three worlds of CSCL. Can we support CSCL?_, 61-91.
